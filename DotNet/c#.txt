-> Boxing: Converting a value type to a reference type
    - Boxing is the process of converting a value type into an object or another reference-type representation. The value is wrapped in an object.
       - Unboxing extracts the value type from that object. Boxing can have performance and allocation overhead, which is one reason generic collections

-> In Entity Framework (EF), an entity is a standard C# class that maps directly to a table in your relational database.
    - The Entity Class maps to a Database Table.
    - An Entity Instance (an object created using new) maps to a Table Row.
    - Entity Properties map to Table Columns.
-> Entity Framework Core (EF Core) is Microsoft's Object Relational Mapper (ORM) for .NET. It allows developers to interact with relational databases using C# objects instead of writing raw SQL queries.
    - What is ORM? - A technique for converting data between a relational database and an object-oriented programming language.
-> In an ASP.NET Core application, the Controller handles incoming HTTP requests and delegates the work to the Service Layer. The Service 
   Layer contains the business logic and coordinates the application's operations. It interacts with the Repository, which is responsible for 
   data access and CRUD operations. The Repository uses Entity Framework Core's DbContext to communicate with the database. Entity Framework 
   Core is an ORM that maps C# objects to database tables and translates LINQ queries into SQL, allowing us to work with the database using 
   strongly typed C# code instead of writing raw SQL.
-> Dependency Injection is a design pattern that provides the required dependencies of a class from an external container instead of creating 
   them inside the class. It promotes loose coupling, improves maintainability, and makes unit testing easier. ASP.NET Core provides a built-in 
   dependency injection container supporting Singleton, Scoped, and Transient lifetimes.
   - service lifetimes in DI ::
      - Transient = new every time ( Use when: the service is lightweight and doesn't need to maintain state. )
      - Scoped = one per request/scope ( Use when: the service should live for the duration of a request. )
      - Singleton = one for the entire application ( Use when: you intentionally want shared application-wide state or an expensive-to-create, thread-safe service. )
   - types of DI ::
      - Constructor Injection = The most common and recommended approach. Dependencies are provided through the class constructor.
      - Property Injection = Dependencies are set through public properties. Less common and can lead to partially constructed objects.
      - Method Injection = Dependencies are passed as parameters to methods. Useful for optional dependencies or when a dependency is only needed for a specific method.

-> A common mistake is injecting a Scoped service into a Singleton, known as a captive dependency, because the Singleton can end up holding a 
   reference to a request-scoped object after that request has finished
    - Detection: Add ValidateScopes and ValidateOnBuild in development:: ValidateScopes detects incorrect lifetime usage such as injecting a 
    scoped service into a singleton. ValidateOnBuild validates service registrations when the container is built, so missing or unresolvable dependencies are detected during application startup instead of at runtime

-> Struct vs Classes :: A struct is a value type, so assigning it to another variable copies its value. A class is a reference type, so assigning
   it copies the reference, meaning both variables can refer to the same object. Structs are generally used for small value-like data, while classes are used for objects with identity, state, and behavior.
-> Controller :: A Controller is the entry point for handling incoming HTTP requests in an ASP.NET Core application. It receives client 
   requests, validates input, invokes the business logic through services, and returns an HTTP response to the client.
-> Service Layer :: The Service Layer contains the business logic of the application. It acts as an intermediary between the Controller and the Repository.
-> Repository :: The Repository Pattern abstracts data access logic from the rest of the application. It is responsible for performing CRUD operations against the database.
-> DBContext :: DbContext is the primary class in Entity Framework Core that manages the connection to the database, tracks entity changes, and translates LINQ queries into SQL queries.
-> LINQ :: LINQ (Language Integrated Query) is a feature in C# that provides a consistent and type-safe way to query and manipulate data from different sources such as collections, databases, XML, and APIs.
