-> In Entity Framework (EF), an entity is a standard C# class that maps directly to a table in your relational database.
    - The Entity Class maps to a Database Table.
    - An Entity Instance (an object created using new) maps to a Table Row.
    - Entity Properties map to Table Columns.
-> The Repository Pattern abstracts data access logic from the rest of the application. It is responsible for performing CRUD operations against the database.
->Entity Framework Core (EF Core) is Microsoft's Object Relational Mapper (ORM) for .NET. It allows developers to interact with relational databases using C# objects instead of writing raw SQL queries.
-> In an ASP.NET Core application, the Controller handles incoming HTTP requests and delegates the work to the Service Layer. The Service Layer contains the business logic and coordinates the application's operations. It interacts with the Repository, which is responsible for data access and CRUD operations. The Repository uses Entity Framework Core's DbContext to communicate with the database. Entity Framework Core is an ORM that maps C# objects to database tables and translates LINQ queries into SQL, allowing us to work with the database using strongly typed C# code instead of writing raw SQL.
-> Dependency Injection is a design pattern that provides the required dependencies of a class from an external container instead of creating them inside the class. It promotes loose coupling, improves maintainability, and makes unit testing easier. ASP.NET Core provides a built-in dependency injection container supporting Singleton, Scoped, and Transient lifetimes.
-> EF core generates sql from LINQ queries
-> LINQ is a C# language feature used to query data from various sources such as collections, XML, and databases using a consistent syntax
-> A common mistake is injecting a Scoped service into a Singleton, known as a captive dependency, because the Singleton can end up holding a reference to a request-scoped object after that request has finished
-> a longer-lived service should not directly depend on a shorter-lived service.
-> A DbContext is not thread-safe and is designed to represent one unit of work (typically one HTTP request).
-> Custom middleware is a user-defined component that can inspect or modify HTTP requests and responses before passing control to the next middleware.
